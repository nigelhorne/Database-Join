   97: =head1 DESCRIPTION
   98: 
   99: C<Database::Join> merges two or more L<Database::Abstraction> objects into a
  100: single logical view.  Each component database is queried independently through
  101: its own C<Database::Abstraction> interface; the results are then combined
  102: in Perl memory using a shared key column (C<join_column>).
  103: 
  104: The module exposes the same read-only API as C<Database::Abstraction>:
  105: C<selectall_arrayref>, C<selectall_array>, C<fetchrow_hashref>, C<count>,
  106: C<columns>, C<schema>, C<updated>, and the C<AUTOLOAD> column shortcut.
  107: 
  108: =head2 Join semantics
  109: 
  110: The C<join_type> parameter controls what happens when a key value exists in
  111: some databases but not all:
  112: 
  113: =over 4
  114: 
  115: =item C<left> (default)
  116: 
  117: All rows from the I<primary> (first) database are returned.  Columns from
  118: subsequent databases are filled in where a matching row is found and omitted
  119: where there is no match.
  120: 
  121: =item C<inner>
  122: 
  123: Only rows whose join-column value is present in I<every> component database
  124: are returned.
  125: 
  126: =item C<outer>
  127: 
  128: Every join-column value found in I<any> database is returned.  Missing columns
  129: from databases that lack that key are simply absent from the merged row.
  130: 
  131: =back
  132: 
  133: =head2 Column ownership
  134: 
  135: At construction time C<Database::Join> calls C<columns()> on each database to
  136: build an internal column-to-database index.  When criteria are passed to a
  137: query method, each criterion is routed to the database that owns the column.
  138: 
  139: The C<join_column> itself is treated specially: criteria on it are broadcast
  140: to I<all> databases so that each database fetches only the relevant rows.
  141: 
  142: When the same non-join column name exists in more than one database, the
  143: I<last> database's value overwrites earlier ones in merged rows.
  144: 
  145: =head1 LIMITATIONS
  146: 
  147: =over 4
  148: 
  149: =item *
  150: 
  151: In-memory join only.  Not suitable for very large result sets.
  152: 
  153: =item *
  154: 
  155: The C<query()> chained builder and C<execute()> raw SQL are not supported.
  156: 
  157: =item *

  159: Only equi-joins on a single shared key column are implemented.  When the join

  279: =head2 join_map - joining on differently-named columns
  280: 
  281: By default every component database must have a column whose name matches
  282: C<join_column>.  If a database calls that column something different, declare
  283: the mapping with C<join_map>.
  284: 
  285: C<join_map> is a hashref.  Each B<key> is the B<zero-based position> of a
  286: database in the C<databases> array (0 = first, 1 = second, and so on).  Each
  287: B<value> is the name that B<that database> uses for the join key.  Databases
  288: not listed in C<join_map> are assumed to already have a column named
  289: C<join_column>.
  290: 
  291: Throughout the merged view the join key is always referred to by
  292: C<join_column>; the local alias is never exposed in returned rows, in
  293: C<columns()>, or in C<schema()>.
  294: 
  295: B<Example> - cities table uses C<statecode>; state-names table uses C<entry>:
  296: 
  297:     #                       index 0     index 1
  298:     my @databases = (      $cities,    $stnames  );
  299:     #  column name:       'statecode'  'entry'
  300:     #  join_column:       'statecode'  - already matches, no map needed
  301:     #                                  - different name, declare it:
  302: 
  303:     my $join = Database::Join->new(
  304:         databases   => \@databases,
  305:         join_column => 'statecode',
  306:         join_map    => { 1 => 'entry' },   # $stnames (index 1) calls it 'entry'
  307:     );

  309:     my $rows = $join->selectall_arrayref();           # rows use 'statecode'
  310:     my $row  = $join->fetchrow_hashref(statecode => 'CA');

  312: If you are adding a database with C<add_database> instead of listing it in
  313: the constructor, pass C<join_column> to name the incoming database's local
  314: column:

  316:     my $join2 = Database::Join->new(databases => [$cities], join_column => 'statecode');

  322: =head2 filters - permanent per-database row filters
  323: 
  324: Normally every row in a component database is a candidate for the merged view.
  325: C<filters> lets you restrict a database to a subset of its rows permanently,
  326: without repeating the criterion on every query call.  The typical use case is
  327: to exclude stale, inactive, or out-of-range rows from the logical view
  328: altogether so callers never see them.
  329: 
  330: C<filters> is a hashref.  Each B<key> is the B<zero-based position> of a
  331: database in the C<databases> array (same numbering as C<join_map>).  Each
  332: B<value> is a criteria hashref in the same format as C<selectall_arrayref>
  333: accepts: plain scalars, operator hashrefs (C<< { '>' => 60 } >>), or any
  334: other form C<Database::Abstraction> supports.
  335: 
  336: B<Key-set semantics>: a filtered database always acts as an inner-join
  337: partner for key-set resolution, regardless of C<join_type>.  Any join-key
  338: value not present in the filtered result is excluded from the merged output
  339: entirely.  This ensures that the filter reduces the view rather than merely
  340: hiding secondary-database columns.
  341: 
  342: B<Criteria merging>: when a query call also supplies a criterion for a column
  343: that already has a base filter, the two are combined:
  344: 
  345: =over 4
  346: 
  347: =item *
  348: 
  349: When both the base filter and the query criterion are operator hashrefs
  350: (e.g. C<< { '>' => 60 } >> and C<< { '<' => 365 } >>), their operators are
  351: merged so that I<both> constraints apply (AND semantics).
  352: 
  353: =item *
  354: 
  355: When either value is a plain scalar, or the operators conflict, the
  356: query-time criterion wins and the base filter for that column is ignored.
  357: 
  358: =back

  360: B<Example> - only show orders placed more than 60 days ago:
  361: 
  362:     #                      index 0       index 1
  363:     my $join = Database::Join->new(
  364:         databases   => [ $customers,  $orders ],
  365:         join_column => 'entry',
